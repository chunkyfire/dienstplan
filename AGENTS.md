- This repository is public and holds code only. Never commit staff names, plans, wishes or keys: no fixtures with real names, no data files. Real data lives in the Supabase tables `dp_*`.
- One app, three tabs (`SuiteTabs`): Aktuell (`#/`), Planung (`#/planung`), Einstellungen (`#/einstellungen`). Hash routing because GitHub Pages serves static files only.
- The components were written against TanStack Start. `src/shim/router.tsx` and `src/shim/start.ts` stand in for it (aliased in `vite.config.ts` and `tsconfig.json`); `src/lib/*.functions.ts` are thin browser calls into the server.
- All server logic is `server/core.ts`, one action per function, reached through a single POST endpoint. It only talks to the `Db` interface in `server/db.ts`, so `bun test` runs it against `memoryDb` without Supabase. CI bundles `server/edge.ts` into the Edge Function; do not edit `supabase/functions/dienstplan/index.ts`.
- Two access levels: the shared site password opens the live plan; wishes need a personal sign-in (name + own password, first time with a one-time invite code from a planner). Sessions are signed tokens (`server/session.ts`), not Supabase Auth, so no e-mail addresses are needed.
- Wish privacy is enforced on the server: `setWish` takes the person from the session, never from the request, and `planning` sends other people's wishes only to planners. Everyone else gets counts per own level from `hintsFor` (`src/lib/wishes.ts`), and none when the level has fewer than three other people. `server/server.test.js` checks that no name or id leaks.
- Swap suggestions come only from the deterministic solver (`src/lib/swapSolver.ts` + `src/lib/arbzg.ts`); the AI assistant calls it as a tool and must never invent swaps.
- The staff table is the single staff list: its level wins over the level printed in a plan, the name is the join key to plan entries, and the Chefarzt level never steps in. Deactivate people instead of deleting them so old plans stay readable.
- Uploading, removing and approving plans is for planners; the stand-in list can be changed by anyone with the site password.
